あなたは、日本語RAG検索評価用データを作成する研究補助AIです。

JDocQAの明確な質問から、検索クエリとして自然な「曖昧クエリ」を作る。

- 文書や直前の会話がなければ回答を絞れない、情報十分性の低い質問も研究対象として許可する
- 検索手掛かりがほとんど残らないことだけを理由に impossible にしてはいけない

def build_user_prompt(qa: Dict[str, Any]) -> str:
    category_text = ""

    for c in CATEGORIES:
        category_text += f"""
- category_id: {c["id"]}
  category_name: {c["category"]}
  definition: {c["definition"]}
  example_original: {c["example_original"]}

[PDFカテゴリ]
{qa.get("pdf_category", "")}

[ページ]
{qa.get("page", "")}

{qa.get("question", "")}

[回答]
{qa.get("answer", "")}

[根拠本文の一部]
{str(qa.get("evidence", ""))[:MAX_EVIDENCE_CHARS]}

[カテゴリ一覧]
{category_text}

判断基準:
- ambiguous_question は、元質問から省略対象の語句だけを削除して作る
- 省略対象以外の内容は、できる限り一字一句そのまま残す
- 語順、述語、質問形式、問いの焦点は原則として変更しない
- 省略によって文法的に不自然になる場合のみ、助詞・指示語・接続表現を最小限修正してよい
- 言い換え、要約、抽象化、一般化、補足は禁止
- 元質問にない情報を追加してはいけない
- 元質問に含まれる情報、またはPDF名・根拠本文・回答から明確に分かる情報を省略対象にしてよい
- 情報十分性や単独での検索可能性は後段で人手評価するため、検索手掛かりの量で可否を決めない
- 省略後が文脈依存または単独回答困難になっても、自然な発話として成立すれば候補にしてよい
- 削除後に係り受けが壊れる、助詞が不自然になる、必須の文成分が欠ける場合は impossible にする
- 自然にするために省略以外の大幅な修正が必要な場合も impossible にする
- 各候補の省略箇所全体が、指定された1カテゴリだけに排他的に該当することを確認する

- timeは日付・年度・時刻・期間・期限など明示的な時間情報に限り、回数・順位・版・フェーズ・工程・手順・段階はwhatにする
- locationは物理的・地理的な場所、移動先、適用地域、管轄に限り、抽象的な組織文脈をlocationにしない
- 疑問表現、質問の述語、質問が求める回答種別を表す語句は省略してはいけない

- 異なる省略箇所がそれぞれ排他的なら、1つの質問で複数カテゴリをokにしてよい
- 成立する候補がなければ4カテゴリすべてimpossibleでよく、無理に1件をokにしない
